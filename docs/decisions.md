# Decisions

Choices the spec left open, the option picked, and why. Newest at the bottom of each phase.

## Phase 1 — Skeleton

| # | Decision | Why |
|---|---|---|
| 1 | **Server-side sessions** (`auth_sessions` table). The cookie holds a random token; only its sha256 is stored. | Logout really revokes the session; logging out on the phone doesn't kill the desktop session. |
| 2 | **CSRF = per-session token.** It is sent in a readable `mh_csrf` cookie and checked against the `X-CSRF-Token` header on every non-GET request. Login is exempt. | Combined with `SameSite=strict`, this covers CSRF without extra libraries. Login CSRF is mitigated by SameSite. |
| 3 | **Login rate limit is in-process**: 5 failures per IP per 5 min, configurable. | One user, one API process. Move it to Redis if the API is ever scaled out. |
| 4 | **Single user is bootstrapped from env** (`MHSQUARE_ADMIN_EMAIL/PASSWORD`) on first API start, only when no user exists. Placeholder passwords are refused. | Simplest single-user setup. `scripts/setup.sh` generates a random password. |
| 5 | **UI served by nginx on the same origin**, proxying `/api` to the API. | Same-origin cookies work with `SameSite=strict`, there are no CORS preflights, and SSE works with `proxy_buffering off`. CORS is still restricted to `MHSQUARE_UI_ORIGIN` for the Vite dev server. |
| 6 | **The Manim renderer is a long-running service on an `internal: true` Docker network**, not a per-render `docker run`. The container is read-only, uses a tmpfs `/tmp`, runs as non-root, drops all caps, sets `no-new-privileges`, and has CPU/mem/pids limits. Phase 4 adds a subprocess timeout plus rlimits per render. | The alternative is mounting the Docker socket into the worker, which is root-equivalent on the host. That is a bigger risk than the untrusted code it would isolate. An internal network has no internet egress. |
| 7 | **Migrations run at API start** (`alembic upgrade head`). The worker waits for API health. | No separate migrate step to forget. |
| 8 | **The gitleaks hook has two paths.** `.pre-commit-config.yaml` is for the pre-commit framework. `.githooks/pre-commit` has zero dependencies and runs the gitleaks binary or the `zricethezav/gitleaks` Docker image. `scripts/setup.sh` installs the latter. | The dev host has no Python, so the pre-commit framework can't be assumed. |
| 9 | **Fonts are self-hosted** via `@fontsource-variable/*` (Inter, JetBrains Mono). | The PWA works offline and makes no third-party font requests. |
| 10 | **shadcn/ui components are hand-added** under `ui/src/components/ui` (same pattern: cva + tailwind-merge). Tailwind v4 with tokens in `@theme`. | shadcn is copy-in code anyway. This avoids the CLI's interactive init. |
| 11 | **LiteLLM uses the `main-stable` image tag** and its own `litellm` database in the shared Postgres. | Virtual keys and budgets need a DB. Pin a specific tag once the stack is validated. |
| 12 | **IDs are UUIDs** (SQLAlchemy `Uuid`). Tests run against SQLite. | Portable. No sequential IDs leak in URLs. |

## LLM settings from the UI (requested after phase 1)

| # | Decision | Why |
|---|---|---|
| 13 | **Provider keys, model IDs and the mhsquare virtual key live in `local/llmconfig.env`** (gitignored). They are edited from Settings → AI providers. Keys are write-only through the API: reads return `configured` plus a `…last4` hint. | Requested: configure everything from the UI and never commit it. |
| 14 | **The API writes the file but never uses provider keys.** All model calls still go through LiteLLM with the virtual key. This is a narrow deviation from "backend only knows the LiteLLM URL + virtual key": the API also holds the LiteLLM master key, used only for `/key/generate` and `/key/update` (the budget screen). | Removes the manual curl step for creating the budgeted key. |
| 15 | **LiteLLM is wrapped by `litellm/entrypoint.sh`.** It loads `llm-defaults.env` and then `llmconfig.env` (parsed, never `source`d), and restarts the proxy when either changes, polled every 3 s. Lines starting `MHSQUARE_` are ignored for change detection. | Applying new keys doesn't need the Docker socket in the API, and saving the budget key doesn't bounce the proxy. |
| 16 | **`local/` is mounted as a directory**, not as a single file. | Single-file bind mounts don't follow atomic rename, and Docker creates a directory when the file is missing. |
| 17 | **Model aliases are provider-neutral**: `planner-llm`, `code-llm`, `code-llm-backup`, `image-gen`, `video-gen`, `video-gen-fast`. | The provider behind an alias is now a UI choice. |
| 18 | **Strict validation of values**: keys must be 8–512 printable ASCII characters with no whitespace. Model IDs must match `provider/model` with a safe character set. | Prevents newline/env injection into the file the proxy loads. |

## Phase 2 — Ingest

| # | Decision | Why |
|---|---|---|
| 19 | **WhisperX runs in its own `transcriber` container** (backend image `ml` target: CPU torch 2.8 + whisperx 3.8.6, about 5 GB). It consumes only the Celery `transcribe` queue with concurrency 1. Models are cached in the `models` volume. The api/worker images stay slim. | The spec allows either. Keeping torch out of the API image keeps it small, and transcription never starves other tasks. |
| 20 | **Default Whisper model is `small`** on CPU int8 (`MHSQUARE_WHISPER_MODEL`). Word timing comes from wav2vec2 forced alignment, so it's accurate even with small ASR models. | A good speed/accuracy trade-off on CPU. Use `medium` or `large-v3` if a GPU is added. |
| 21 | **A filler-laden `initial_prompt`** ("Umm, let me think like, hmm…") is passed to Whisper. | Whisper normally drops disfluencies. With the prompt it kept "Um," and "uh," in the real test. |
| 22 | **"like" counts as a filler only when set off by punctuation** ("like,") or when it's the first word. | "I like Kafka" must not be cut. |
| 23 | **Cut shape**: a gap containing fillers is cut from the filler through the dead air, keeping up to `keep_pause_ms` (150) of natural pause next to real speech. Pauses longer than `silence_ms` (600) shrink to 2 × 150 ms. Edges are trimmed fully. Cuts shorter than 80 ms are dropped. | Sounds natural. It never clips real words. |
| 24 | **Cut boundaries snap to the project frame grid** (e.g. 1/30 s) before they are applied to both the audio and the face-cam. | Per-segment frame rounding would otherwise accumulate audio/video drift over hundreds of cuts. |
| 25 | **Audio cuts use trim + concat with 4 ms fades** per segment. | Avoids clicks at cut points. |
| 26 | **The face-cam is cut once into a CFR H.264 CRF 16 intermediate** at the project fps. There's an optional `facecam_offset_ms` for when the camera and the mic didn't start together. | One high-quality encode. The final render happens once in phase 7, per principle 8. |
| 27 | **Loudness cleanup = high-pass 80 Hz → gain → 4×-oversampled peak limiter at −1.5 dBTP**, iterated with a secant step until within ±0.5 LU of −14 LUFS (max 4 passes, gain capped at ±30 dB). It is not ffmpeg `loudnorm`. | Single- and two-pass loudnorm both undershot speech: −16.8 and −16.3 LUFS on the test clip. Loudnorm can't add the needed gain under the peak ceiling, so it falls back to dynamic mode. The new chain measured −14.0 LUFS / −1.5 dBTP. The cleaner stays pluggable (`media._CLEANERS`). |
| 28 | **Uploads are resumable chunked PUTs** (`POST /projects/{id}/uploads` → `PUT /uploads/{id}?offset=` in 8 MB chunks → `POST …/complete`), plus single-request multipart `POST /projects/{id}/assets` for small files. Checks: an extension allow-list, a declared-size limit, magic-byte sniffing, ffprobe stream checks, and a stored extension derived from the sniffed type. | Meets the spec's "chunked upload for large files". A resumed upload asks the server for its offset. |
| 29 | **Signed media URLs**: HMAC of asset id + expiry (6 h TTL), with single-range `Range` support. They don't need the session cookie. | `<audio>`/`<video>` tags can scrub, and links expire. |
| 30 | **Ingest status is polled by the UI** (every 2 s while busy) in phase 2. SSE arrives in phase 6. | Simplest for now. The state lives in the DB either way. |
| 31 | **The UI must run vitest from an uppercase `D:\` cwd on Windows.** A lowercase drive letter loads two vitest instances ("failed to find the current suite"). | Known Windows path-casing issue. CI and Docker are unaffected. |

## Phase 3 + generation slice (after the reference videos)

| # | Decision | Why |
|---|---|---|
| 32 | **Code animations are HTML/CSS + GSAP scenes rendered by a sandboxed headless Chromium** (`renderers/motion`). This replaces Manim as the default `code_animation` generator (`routing.yaml: generator: html_motion`). Manim stays available as a generator option. | The reference "tech" video (glass cards, blur, Inter typography, chips, wires, code highlights) is native to HTML/CSS. Manim can't produce that look. Routing stays config-driven. |
| 33 | **Rendering is deterministic.** Date/performance/rAF are frozen. Math.random is seeded. CSS animations and transitions are disabled. The renderer seeks the GSAP timeline per frame, captures via CDP PNG (`optimizeForSpeed`) and pipes into ffmpeg with exactly `duration × fps` frames. | Frame-exact durations (the spec's time-fit requirement). CDP capture is about 4× faster than `page.screenshot`: roughly 5 s of compute per 1 s of 1080p video. |
| 34 | **Renderer sandbox**: internal network (no egress), every page request aborted (`route → abort`), read-only rootfs, tmpfs /tmp, non-root, caps dropped, CPU/mem/pid limits, 180 s render timeout, 2 concurrent renders. GSAP 3.15.1 and fonts are vendored into the image. Static checks reject URLs, network/timer/storage APIs, `<script>/<img>/<iframe>`, eval and CSS animations before rendering. | Principle 5: LLM-written code is untrusted. The checks also give the LLM precise errors to fix. |
| 35 | **Two house themes as component kits**: `tech` (navy glass, from the LiteLLM reference) and `story` (flat teal cartoon, from the "Meet Robin" reference). Each is a CSS file plus prompt docs listing the classes and the reference's signature moves. | Consistent, polished output across every shot. The LLM composes known components instead of inventing styles. |
| 36 | **Story characters are drawn once per project as an SVG rig** (`.head .eyes .mouth .arm-l .arm-r .body .legs`) by the code LLM, stored in `style_guide.character_svgs`, and injected into every story scene via `mhCharacter(id, …)`. | The same character looks identical in every shot (the "Robin" requirement) without an image model. |
| 37 | **Scenes are synced to the voice.** The scene writer gets each spoken word's time relative to the shot start, and is told to start a beat about 0.15 s before its trigger word. The planner writes briefs as beats tied to words. | Makes the visuals feel natural: what's said is what moves. |
| 38 | **The planner sees numbered transcript segments with exact times** and returns segment ranges. The backend turns them into contiguous, word-aligned shot times. ai_clip shots over 8 s are split. One retry with validation errors. | The LLM can't produce gaps, overlaps or wrong timestamps. |
| 39 | **One fix round per scene.** A static-check or render error goes back to the LLM once. A second failure leaves the shot `failed`, with logs visible in the UI. | Spec §5.4 step 4. |
| 40 | **LLM error classification → shot state**: budget/quota/"no credits" → `paused_budget`. Content policy → `needs_edit` (editing the brief re-enables it). 429 → backoff with jitter ×5. 5xx/timeout → 3 tries, then the fallback alias. | Spec §7. |
| 41 | **Cache key** = sha256 of visual type, model alias, prompt + theme, style-guide version, seed, duration, resolution, generator, feedback and shot start. A hit reuses the stored file at $0. | Spec "never pay twice". "Regenerate with same seed" without a note is free. |
| 42 | **`still_image` = AI illustration + an LLM-written overlay scene** (push-in, callouts) rendered by the same renderer. `ai_clip` falls back to that path until a video model is configured. | Neither this Gemini key (free tier) nor OpenAI/OpenRouter (no credit) can generate images or video yet. `config/routing.yaml` (local) limits the planner to code_animation/text_card/a_roll for now. |
| 43 | **Draft narration via TTS** (`tts` alias, default Gemini 2.5 Flash TTS): the script is spoken by an AI voice and used as the narration audio. | Lets you test a script end to end before recording. It isn't recording inside mhsquare, so it stays within scope. |
| 44 | **Proxy preview** (720p, CRF 24): every shot's accepted (else latest) take on the narration. Frame counts come from absolute timeline positions, so there's no drift. Missing shots render as navy placeholders. | Quick review. The single high-quality render and the exports remain phase 7. |
| 45 | **Cost estimate uses explicit per-generator constants** (`services/budget/estimate.py`). | LiteLLM's cost map doesn't know these new model IDs: it reports spend $0. Budget enforcement in phase 6 needs real prices. |

## v2.1 — Simplify AI Style Profile

| # | Decision | Why |
|---|---|---|
| 46 | **The Style Profile is a DB table with immutable versions and one active version.** Saving creates a new version. Old versions can be re-activated, and "reset" re-seeds the v2.1 defaults as a new version. Prompts, the theme CSS, the footer, the lint, canvas geometry and the judge all read the active version. Each take records `style_profile_version`, which is also part of the cache key. | v2.1: editable, versioned, never hard-coded in prompts. |
| 47 | **The brand theme CSS is generated from the profile**: CSS variables for accent (the project's pillar), palette, background/grid and fonts, followed by the static component kit `brand.css` (pills, LEDs, VS Code window, nodes, wires). The old `tech.css` look was removed. The `story` cartoon theme stays, switched to Poppins, with its own palette allowed by the lint. | One source of truth for colours and fonts. |
| 48 | **The footer is injected by mhsquare, not written by the LLM.** It always renders when `footer_on_animations` is on. The lint rejects a hand-drawn handle or tagline. On long-form, the footer's right edge ends before the face-cam zone, so the handle never sits under the circle. | §5.2 asks for the handle on the right; §3.1 puts the circle bottom-right. This resolves the conflict. |
| 49 | **Style lint = regex/colour-distance checks on the LLM's html/css/js**: off-palette colours (neutrals and Dark+ allowed), foreign fonts, macOS dots or `mh-code` heads, buttons/inputs/replay, dashed borders/guide marks, person placeholders, hand-drawn footer. **Layout probe in the renderer** (before rendering any frame): visible content in the face-cam safe zone or text off-stage. Both go back to the LLM in the single fix round. If issues remain after it, they are recorded as warnings and the shot still renders. Security violations always fail. | Spec: "send the issues back once". Failing a whole shot over a colour nit after the fix round would cost more than it saves. |
| 50 | **Canvas per content type.** Long-form: 1920×1080 stage (4K renders at device scale 2), with a bottom-right safe zone of 22%×22%. Shorts: 1080×1440 (3:4) or 1080×1920 (9:16) stage inside a 1080×1920 export, padded with the brand background. | §3.1, §3.2. |
| 51 | **Long-form plans never contain a_roll**: removed from the planner's allowed types and enforced by plan validation. The face cam is composited as a circle in the bottom-right zone (preview now, final render in phase 7) with a pillar-coloured ring. `leave_space` only keeps the zone clear. | §3.1. |
| 52 | **Watermark top-right only on shots without the footer** (face-cam segments, placeholders, or everything when the footer is off). Uses Poppins via ffmpeg drawtext. | §5.2 footer/watermark rule. |
| 53 | **Generator renamed `html_animation`** (with `alt_generator: manim_code`). The old `html_motion` name is still accepted. Model aliases stay provider-neutral (`code-llm`), not the spec snippet's `claude-code-gen`. | Matches v2.1 naming without breaking local configs. |
| 54 | **Brand fonts are bundled**: Oswald (variable) and Poppins 400–700 TTFs from the google/fonts repo, baked into the renderer image. JetBrains Mono comes from Debian. Consolas is proprietary, so the code stack is `Consolas, JetBrains Mono, monospace`. The standalone HTML export embeds Oswald and Poppins as data URIs (~1.2 MB per file). | §5.1 "fonts bundled locally"; exports look identical on any machine. |
| 55 | **Standalone HTML export per take** (`GET /api/takes/{id}/html`): libraries and fonts inline, auto-plays on load, scales with `Math.min(innerHeight/H, innerWidth/W)`. A strict CSP blocks any network access. | §5.1/§5.2: matches the existing HTML-animation workflow. |
| 56 | **Script judge = deterministic checks + LLM rubric.** Deterministic: Devanagari; Hinglish (≥ 2 hits from a curated list without English collisions); presenter intro; first-person credibility (skipped for `short_advice`); shorts length > `warn_words` at `wpm`. The LLM scores the profile's rubric. **Verdict**: `rejected` (any hard fail or English-only fail) → `needs_work` (average < 6) → `good`. | §2. A plain "passed" chip was misleading for weak but rule-abiding scripts. |
| 57 | **Topic repeats**: cosine similarity ≥ 0.78 on `embed` alias vectors (default Gemini `gemini-embedding-001`, free tier), cached per topic, or lexical token overlap ≥ 0.8. If embeddings fail, the check falls back to lexical overlap ≥ 0.5. | §4. Never blocks; it warns. |
| 58 | **"Mark script final" lives on the project page** for now and adds the topic to the registry. Script Studio (v2) will call the same endpoint. | §4 auto-add, before Script Studio exists. |
